# Silkit

[简体中文](README.md) · **English**

A cross-database workbench for MySQL / MariaDB / PostgreSQL / SQLite, on the Windows desktop.
Built with C++20 + Win32 + WebView2; the frontend is plain HTML/CSS/JS with no Node build step.

> `CODEPLAN.md` and `CHANGELOG.md` are currently available in Chinese only.

> Current version: **v1.0.1** (2026-11-15). Progress: **M0–M9 all delivered** — connections → object tree → CodeMirror SQL editor → streaming results (multi-result / EXPLAIN) → tabular data editing → table designer → history / snippets → CSV import, five streaming export formats, SQL dump → settings, safe mode and log redaction → release packaging.
> The full plan and deviation log are in [CODEPLAN.md](CODEPLAN.md).

## M0 Delivered

- A buildable single-file `Silkit.exe` (static CRT, only depends on the system WebView2 runtime)
- Asynchronous IPC: `ipc.call` returns immediately; a worker thread pool posts back `progress / result / error / cancelled` via `ipc.event`
- UI shell: top bar, object tree, SQL editor, result grid, message panel, status bar, draggable splitters
- Five themes + top-bar switcher + shortcuts; theme and window background are persisted, no white flash on startup
- Config written atomically to `%APPDATA%\Silkit\settings.json`; daily logs under `%APPDATA%\Silkit\logs\`
- Self-test entry: "Self-test" in the top bar runs a 3-step async task that can be cancelled mid-run
- `tools/contrast_check.py`: validates key color pairs of all five themes (WCAG 2.1)

## M1 Delivered

- **SQLite driver**: connection options (read-only / busy timeout / foreign keys / `journal_mode` allowlist / `init_sql`), parameterized execution, streaming batches, cross-thread cancellation, error position reporting
- **Session model**: one dedicated thread + task queue per connection; reconnect keeps `sessionId`, transaction state, runtime read-only switching, and the `session.closed` event
- **IPC commands**: `conn.*` (test/open/close/reconnect/ping/stats/set_database/set_readonly), `meta.*` (children/detail/ddl/search/refresh), `query.*` (execute/cancel/explain)
- **Query execution**: `sql_splitter` splits multi-statement SQL and runs it in order, `statement` / `batch` streaming events, error location, `continueOnError`, `maxRows` truncation
- **Frontend**: connection dialog and file picker, lazy-loaded object tree with context menu (reconnect, read-only), query tabs, virtual-scrolling result grid, TSV copy, long-text / BLOB cell viewer, recent queries
- **Security**: DPAPI password storage, redacted `conn.list`, driver-level write interception, identifier quoting and value parameterization
- **Tests**: `silkit_smoke` (pure logic / in-memory database / session) and `sqlite_driver` (driver robustness and session state regression), both run by CTest

## M8 Settings, Security & Polish Delivered

- **Settings panel**: opened from the top-bar gear, with six tabs (General / Editor / Query / Data Grid / Export / About). Language, animation, sidebar width, tab restore, dangerous-operation confirmation, editor font size / indent / wrapping / line numbers / completion, safe mode, max rows / batch size / history limit, page size / row height / NULL text, export encoding / delimiter / NULL literal are all configurable and take effect immediately on save.
- **Config recovery**: `settings.json.bak` is kept before every successful write; a corrupted main config is automatically restored from the backup and rewritten; "Restore defaults" resets in one click.
- **Safe mode**: on by default; `query.execute` and `query.execute_file` check every statement after splitting. `DROP / TRUNCATE / ALTER / GRANT / REVOKE / ATTACH / DETACH / VACUUM` or `UPDATE / DELETE` without `WHERE` return `confirm_required` plus a one-time token; the frontend lists the statements and asks for confirmation, and any change to the statements invalidates the token. Read-only connections still reject writes at the driver layer.
- **Logs & crashes**: all log writes are redacted (password/passwd/pwd/secret/token/api_key, etc.); unhandled exceptions write `%APPDATA%\Silkit\logs\crash-*.log` (version / time / exception code / address / thread); the About page can open the data and log directories directly.
- **Session restore**: restores the last active tab, editor scroll position, sidebar width and collapsed state; sidebar width supports dragging and keyboard adjustment.
- **Themes**: `contrast_check.py` passes all 125 color pairs across five themes (including dialogs, grid and editor tokens).
- **Keyboard & focus**: `Esc` closes settings; shortcuts do not fire while a dialog is open; `:focus-visible` rings cover buttons, inputs and splitters.
- **Tests**: CTest `m8` covers log redaction, settings backup / corruption recovery / reset, dangerous-statement detection and token stability.

## M7 Import / Export / Dump Delivered

- **CSV core**: `io/csv` parses RFC4180 (quote escaping, multi-line fields, CRLF/LF/CR) and quotes on write as needed; auto-detects `,` `;` `Tab` `|` delimiters.
- **Streaming export**: `io/exporter` supports CSV / JSON / SQL / Markdown / HTML with an internal 64KB buffer split on encoding boundaries; SQL emits a multi-value INSERT every 100 rows, JSON keeps numbers unquoted, maps NULL to `null` and binary to hex.
- **Export wizard**: the result-set toolbar and the object-tree context menu share the same dialog; format / encoding / delimiter / header / NULL literal are configurable, progress is reported live and cancellable; writes to `<path>.part` first and replaces the final file only on success, cleaning up automatically on cancel or failure.
- **CSV import wizard**: auto-detects encoding and delimiter after choosing a file and previews the first 20 rows; edit target column names per column (leave blank to skip), optional first-row header / empty-to-NULL / auto-create-table; batch INSERTs run in a transaction, and on failure it rolls back and replays row by row to locate the exact data row and file line number.
- **SQL file execution**: "Execute SQL file" in the toolbar runs statements one by one with `statement` events and progress, supporting continue-on-error and cancel.
- **SQL dump**: whole database or selected tables; schema (`CREATE TABLE` / indexes / foreign keys), data and `DROP TABLE IF EXISTS` can be toggled separately; also uses `.part` files and progress events.
- **Encodings**: UTF-8, UTF-8 BOM, UTF-16LE (with BOM and emoji surrogate pairs), GBK for import and export; without a BOM it validates UTF-8 legality and falls back to GBK when invalid.
- **Tests**: `test_io` (CTest `io`) covers CSV multi-line / quoting / detection, UTF-8↔GBK/UTF-16LE round trips, snippets of all five export formats, 1M-row streaming export, 100K-row import, error rollback with line location, cancel rollback, and dumping a whole SQLite database into an empty database.

## M6 Table Designer & DDL Delivered

- **Three-engine DDL generation**: `db/ddl_builder` generates CREATE / ALTER / DROP / TRUNCATE for SQLite / MySQL / PostgreSQL, covering columns, primary keys, auto-increment, defaults, comments, indexes, foreign keys and MySQL table options.
- **Table designer**: opened from "Design table" in the object tree or "Design" in the toolbar; columns / indexes / foreign keys can be added, removed and reordered, with options, type suggestions, SQL preview and warnings in separate panels; a dirty state prevents accidental closing.
- **Unified preview & token**: `ddl.preview` produces SQL plus an FNV-1a token, and `ddl.apply` verifies the token before executing; any change to the DDL invalidates it, and a failure returns the failing statement, the number of statements already executed and whether a rollback occurred.
- **Complete preview info**: the SQL preview includes affected row count (`0` for CREATE, actual count for DROP/TRUNCATE, "unknown" for ALTER) and risk warnings (dropped columns, shortened length, type change, tightened NOT NULL, possibly failing unique indexes, MySQL non-transactional DDL).
- **Identifier validation**: new table / column / index / foreign-key names are length-checked per engine and validated as UTF-8; control characters, quotes and semicolons are rejected.
- **Dangerous-operation confirmation**: dropping a table / truncating a table / dropping a database requires typing the object name; MySQL shows a non-rollbackable warning, while PG/SQLite use a transaction or savepoint.
- **SQLite limitation hints**: changing a column definition, primary key or foreign key explicitly says "not supported, rebuild the table" instead of silently degrading.
- **Database & object DDL**: create / drop databases for MySQL/PG; view / function / trigger definitions can be viewed as DDL in the detail panel and saved as `.sql`.
- **Tests**: CTest `ddl_builder` covers three-engine SQL generation, token invalidation and parameter validation; `sqlite_fixture` validates metadata, data and read-only protection of the `data/silkit_test.db` fixture and runs file-database DDL on a temporary copy; `integration_db` completes create table → alter table → rename → truncate → drop → create/drop database on an in-memory SQLite database, a real MySQL 8.4.13 and PostgreSQL 18.7. The fixture can be rebuilt with `python tools/make_test_db.py`.

## M5 Tabular Data Editing Delivered

- **Data grid**: double-click a table/view in the object tree to open an editable grid (`grid.js` virtual scrolling); pagination, sorting, search, filters (operator + value + AND combinations).
- **Row identity & read-only**: automatically detects a primary key / unique non-null index / SQLite `rowid`; tables without a safe row identifier become read-only with an explanation.
- **Inline-edit state machine**: insert rows, delete rows, edit cells; dirty cells / inserted / deleted rows are highlighted; toolbar for insert / delete / save / undo / refresh / exact row count.
- **Transactional save**: `table.apply` runs INSERT/UPDATE/DELETE in a transaction (SAVEPOINT if the connection is already in one); any failing statement rolls everything back and points to the failing row (`clientIndex`). An SQL preview is shown before saving.
- **Cell viewer**: double-click / right-click opens long text, JSON, image and HEX views with save-as.
- **Copy / export**: range selection, TSV copy, SQL / INSERT copy formats.
- **Validated against real servers on all three engines**: CRUD, unique-key conflict rollback and exact row count pass on MySQL 8.4.13 and PostgreSQL 18.7; `test_table_ops` (SQLite) covers per-engine SQL building and rollback.

## M4 Query Workspace Delivered

- **Editor**: CodeMirror 5 (vendored), SQL keyword / string / comment highlighting follows theme tokens; each tab has its own Doc (independent undo history, cursor and scroll).
- **Autocomplete**: `Ctrl+Space` or after typing 2 characters; tables / columns come from the `meta.children` metadata cache plus engine keywords.
- **Execution scope**: `Ctrl+Enter` runs all / selected text, `Ctrl+Shift+Enter` runs the statement at the cursor; the toolbar can switch the default scope.
- **Result panel**: sub-tabs for multiple result sets; one-click CSV/JSON export; execution plan (EXPLAIN) sub-tab with all three dialects; error location in the message panel.
- **Files**: open / save / save-as `.sql` (`Ctrl+S`), drag-and-drop supported; backend `app.read_file` / `app.save_file` restrict to text extensions ≤16MB.
- **History / snippets**: 5,000 history entries + 200 snippets, searchable, click to refill / insert, written to both localStorage and settings.json.
- **Formatting**: lightweight SQL formatter (`Shift+Alt+F` or toolbar) — uppercases reserved words, breaks on main clauses, indents parentheses, wraps comma lists.

## M2 / M3 Delivered and Validated Against Real Servers

- **MySQL / MariaDB**: static `libmariadb`; connection (SSL / charset / timeout / read-only), `mysql_use_result` streaming, prepared-statement parameterization, `KILL QUERY` cancellation, `information_schema` metadata and `SHOW CREATE` DDL, friendly error-code hints.
- **PostgreSQL**: static `libpq`; `PQconnectdbParams` (`search_path`, `bytea_output=hex`), `PQsetSingleRowMode` single-row streaming, `PQsendQueryParams` parameterization, `PQcancel` cancellation, `pg_catalog` metadata, `pg_get_*def` DDL with simplified catalog reconstruction, SQLSTATE error mapping.
- **Shared**: `db/engine_dialect.*` centralizes type mapping / error hints / metadata SQL; `ipc/commands_meta_engine.*` dispatches `meta.*` per engine while the SQLite path stays unchanged; `conn.set_database` uses `USE` / reconnect / ATTACH depending on the engine.
- **Frontend**: engine selector in the connection dialog, MySQL/PG form (host / port / user / password / database / schema / charset / SSL / timeout / init SQL), DPAPI password storage, test connection; the object tree shows engine badges and passes `schema` through.
- **Tests**: `engine_dialect` (types / errors / SQL generation, no server needed), `integration_db` (connects to real servers via `SILKIT_MYSQL_*` / `SILKIT_PG_*` environment variables, skipped when unset), `e2e_real_db` (14 checks × 2 engines against real databases; optional `SSL-01~03` covers MySQL-protocol servers that do not advertise `CLIENT_SSL`, enabled with `--mysql-nossl-host`). Run everything with `python tools/e2e_runner.py`; see `CODEPLAN.md` §12.4 / §12.9.
- **Connection failure diagnostics**: "Copy info" at the right edge of the error bar and the error toast copies the full error (code / SQLSTATE / detail / hint) plus connection context, without the password. When MySQL reports `2026 TLS/SSL error`, follow the hint and set "Charset / SSL" to `disable` (or keep `prefer` to downgrade automatically).

> Validation record: MySQL 8.4.13 and PostgreSQL 18.7 both passed end-to-end checks for connect, `SELECT 1`, object tree (databases / folders / tables / columns / details / search / DDL), cancellation and error hints (against locally installed MySQL 8.4.13 and PostgreSQL 18; the status bar previously showed the PG version as `18.0.7`, now fixed to `18.7`).
> Known gaps: PG table DDL is a simplified catalog reconstruction and differs from `pg_dump --schema-only`; MariaDB 11 and PostgreSQL 13–16 were not deployed per version (same driver path); the type matrix and performance validation (5,000 tables / 1,000-table metadata) are not measured yet.

## Architecture Notes

- **Never block the UI thread**: `Bridge::HandleInvoke` runs synchronously on the UI thread, so `ipc.call` only validates arguments and enqueues work; everything expensive goes to an `AsyncRouter` worker.
- **Event delivery**: workers post `Bridge::Emit("ipc.event", …)` into a JS queue, executed on the UI thread by `Window::ExecuteJsFromQueue`.
- **No white flash**: an inline script in `index.html` reads `localStorage` and sets `data-theme` before CSS loads; the C++ side sets the window class background brush and WebView2 `DefaultBackgroundColor` to the theme background at window creation.
- **Config**: `settings.set` recursively merges and writes atomically; the frontend only submits a patch.
- **Driver isolation**: `db/Connection` abstraction + `DriverRegistry`; the UI only knows the unified model, so M2/M3 only needed new drivers.
- **Session affinity**: one Session thread per connection, driver objects are never used across threads; `Cancel()` is designed separately to be callable cross-thread.
- **Streaming results**: `query.execute` emits `statement` / `batch` per statement, the first batch carries column metadata, and results are marked `truncated` once `maxRows` is reached.

## Known Limitations (v1.0.1)

- **Platform**: Windows desktop only, depends on the system WebView2 runtime; macOS / Linux are not supported yet.
- **Import / export / dump**: CSV import reads the whole file (256MB cap); SQL file execution reads the whole file (512MB cap) and then executes statement by statement, without chunked streaming; SQL dumps cover only table schema and data — save view / function / trigger definitions as `.sql` from the detail panel.
- **Dump compatibility**: PostgreSQL schema is reconstructed by `LoadDdlDefinition` and differs from `pg_dump` output; cross-engine restores need manual type-dialect adjustments.
- **Result streaming backpressure**: `query.ack` backpressure is not implemented; very large result sets rely on `maxRows` truncation, so explicitly limit returned rows.
- **PostgreSQL table DDL**: a simplified catalog reconstruction that differs from `pg_dump --schema-only`; editing view / function / trigger definitions means viewing the DDL in the detail panel and saving `.sql` manually — the table designer currently covers tables only.
- **Engine version coverage**: validated against real MySQL 8.4.13 and PostgreSQL 18.7; MariaDB 11 and PostgreSQL 13–16 were not deployed per version (shared driver path, not separately verified).
- **Performance validation**: large-scale scenarios such as 5,000 tables / 1,000-table metadata and the type matrix are not measured yet.
- **i18n**: Chinese and English cover the top bar, sidebar, editor toolbar, result tabs, status bar, settings and danger confirmations; dynamic text in the object tree, history, table designer and import/export dialogs is still Chinese and will be filled in gradually.
- **Session restore**: restores the active tab, editor scroll position and sidebar layout; scroll positions of the result grid and object tree are not persisted.
- **DPI**: the framework enables Per-Monitor V2; 100% / 150% were checked visually, but 200% scaling and multi-monitor switching are not documented yet.
- **Crash diagnostics**: only a text crash log is written, no minidump; no remote error reporting (local-first).
- **Remote connections**: SSH tunneling is not supported yet (planned for v1.1); direct connections require the database to be network-reachable.

> In DevMode, `frontend/` must sit next to the exe (or at `build\Release\..\..\frontend`).
